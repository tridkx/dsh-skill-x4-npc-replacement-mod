## §11.1 动作时四肢朝反方向弯、手指被拉长

**判据**：每顶点到主导骨**线段**的平均距离，按部位分组，与 vanilla 同口径比。
vanilla 手指 1.11 / 手掌 5.34 cm；本例出问题时有 23.9 / 17.3 cm。

**根因**：顶点在绑定姿态下离它的主导骨太远（本例手 42 cm），动画一播就被甩错方向。

**修法**：
1. 先确认坐标映射符号（`01-coordinate-frames.md` §3）—— 符号错了残差也会堆在四肢；
2. 再做**逐骨绑定姿态转移**（`02-retargeting.md` §4.1–§4.3）；
3. 骨轴用**主链第一个子骨**（骨盆尤其容易错）；
4. 折叠骨**锚定**到最近的直接骨（§4.4）。

**不要走的路**：用"绕肩旋转手臂顶点"这类**局部 hack** 去救。本例在这条路上卡了很久
（误差 20.6 → 21.7）。局部 hack 治不了"整条链的比例差"。

## §11.2 脸整个消失 / 衣裤鞋透明、能看穿到对面内壳

**判据**：`check_normals.py` → 比例 < 0.5 即确诊（工程阈值 0.45）；
有源法线时优先用 `check_winding.py`（`01-coordinate-frames.md` §3.4）。

**根因**：三角形绕序翻转（法线朝内），引擎剔除正面。
**迷惑点**：所有基于顶点位置的检查全部正常（指标、包围盒、骨骼叠加）。

**修法**：建网格时反转三角形 `(a,b,c) → (c,b,a)`；同时确认坐标映射用的是
**物理正确**的那一支（`(x, z, y)`，det = −1）。

> 相关的反向错误：若映射写成 `(x, −z, y)`（det = +1），绕序正常但**前后镜像**，
> 残差堆在四肢而躯干正常 —— 见 §11.1。

## §11.3 腰部有莫名其妙的横向色带 / 衣服颜色与原版对不上

**判据**：用材质染色渲染（`color_type='MATERIAL'` + `material.diffuse_color`）
确认那条带属于哪个材质；再查该材质在源数据里有没有 albedo。

**根因**：源数据里"只有 shader 参数、没有 albedo"的材质（缝线 / 底座类）拿到了手工填的
深色占位，且缺 smoothness 贴图时导出器写死 `Smoothness = 0.5`（本体 0.08 哑光）
→ 深色 + 反光。

**修法**：`04-materials-and-textures.md` §7.3 —— 按 UV 采样主材质求均色 + 继承粗糙度。

> 这类材质常常是**成片几何**（本例夹克缝线 3799 顶点、金属件 7776），不是细线。
> 不要用"提高减面比例"把它减没 —— 那只是掩盖，比例调回来它还会出现。

## §11.3b 身上出现亮粉色 / 洋红的小片

**两种完全不同的原因，先分清**：

| 现象 | 原因 | 修法 |
|---|---|---|
| 某块几何**整片发白 / 粉**，且它是深色部件 | **BC3 块顺序写反**（自研编码器） | `04-materials-and-textures.md` §7.4.2 —— DXT5 是 `[alpha][color]` |
| 小块**刺眼的洋红**（255,0,255） | 游戏**找不到 / 不接受**那张贴图 | 同上 §7.4.1 —— 特别是 16×16 的纯色占位图会被拒 |

**定位顺序**（按这个来最快）：

1. **按用户指的坐标放大实机截图** —— 不要自己猜位置；
2. 确认它属于哪个部件（形状像带扣就是挎带、像手指就是手）；
3. **量那张贴图的源与转换结果** —— 源与结果均值差很远就是编码 / 转换环节的问题，
   不用再怀疑几何或 UV；
4. 确认它走哪条编码分支 —— 带 alpha 的材质走 BC3，这是最容易被忽略的分支。

## §11.4 虎口 / 指间裂开，像平白少了一块皮

**根因**：源角色手指**并拢**、X4 手指骨**张开**；逐骨对齐 = 把手掰开，
而指间的皮没有自己的几何，只是两侧皮肤的过渡 → 撕开。

**修法**：`02-retargeting.md` §4.5 —— **手指权重整体绑到手掌骨**。

**不要取的中间态**：半量混合（各 50%）会让**五根手指各自扭曲**，比两端都差。
要么全跟骨骼、要么全跟手掌。

## §11.5 脚跟悬空、只有前掌着地

**判据**：把脚部顶点按前后分带，看各带的最低 z：

```
             脚跟    足弓    前掌    脚趾
vanilla     -0.15   -0.25   -0.32    1.10
出问题       5.43    3.23   -0.48   -0.59
```

**根因**：不是旋转，是**位移差** —— `Toe0` 的目标比源骨低 3.1 cm，`Foot` 高 2.0 cm，
逐骨各走各的把脚撬斜。

**修法**：`02-retargeting.md` §4.6 —— 整只脚共用踝关节位移 + 地面**双向**对齐。

> 只做"去掉脚骨旋转"只能恢复约 1/4 的偏差，别停在那里。

## §11.6 手指上有一圈圈横纹 / 指根深色斑块

**根因**：切线跟着 UV 走；对**手**做减面会重写手指 UV → 切线空间错乱 →
法线贴图渲染成环纹。

**注意**：workbench 预览**不显示法线贴图**，必须用 EEVEE 复现。

**修法**：手部**完全不减面**（`ratio = 1.0`），并跳过手部的权重平滑
（`03-decimation-and-normals.md` §6.3）。

## §11.7 脸上 / 身上有明显面片，显得粗糙

**判据**：导入成品 `.xac`，量 `|顶点法线 − 面法线|`：`0.000` = 平面着色（错），
`0.4` 左右 = 平滑（对）。

**根因**：两段式管线里**只有 stage1 设了平滑**，stage2 用 `from_pydata`
重建网格时默认回到平面着色，而导出器读 `loop.normal`。

**修法**：两个阶段都设 `poly.use_smooth = True`。
**顺带收益**：消掉法线接缝，导出顶点约 −70%，可以把预算花到面数上。
见 `03-decimation-and-normals.md` §6.1–§6.2。

## §11.8 空间站频闪 / 地图卡死 / 地图彩色斑块

**根因**：资产顶点数远超 vanilla（NPC 是实例化渲染，地图要画全部对象）。

**量级**：vanilla 两个资产合计约 8.3k；本例 9× 稳定、15.5× **频闪复发**、
终版 6.3× 稳定。

**修法**：降 `DECIMATE_RATIO`；**优先提升"法线"而不是"减面"**
（见 §11.7，平滑法线本身就是一大笔预算）。

> 口径：导出器的顶点计数**含 UV / 法线接缝**，比较时要用导出后的数字。
> 细节见 `03-decimation-and-normals.md` §5。

## §11.9 眼球不见 / 偶尔错位不跟头

**两个独立原因**：

1. **几何用错了**：源资产里可能有一个"位置偏低的眼球拷贝"。
   先量源数据各子网格的高度分布，用**与眼睑对齐**的那一个；
2. **look-at 甩飞**：X4 用 look-at 驱动 `left/right_eye_dummy`，而源眼球几何离这两根骨
   很远 → 视线一转就飞出去。**修法：这两根骨上的权重改挂 `Bip01 Head`**
   （稳定优先，放弃眼球随视线转）。

细节见 `02-retargeting.md` §4.7。

## §11.10 头缩在衣领里

**判据**：眼球（或脸顶）与夹克领口的高度差：

```
源数据 7.5 cm    vanilla 9.9 cm    出问题 0.6 cm
```

**根因**：X4 的 `Head` 只比 `Neck` 高 7.8 cm，源的高 13.7 cm。各自对齐 →
头被拽下、领口被推上。

**修法**：`02-retargeting.md` §4.8 —— **头颈共用一份位移**（取两者平均）。

## §11.11 改了 XML 但游戏里没变化

**按可能性排序**：

1. `sel=` 的 XPath 写错 → 游戏**静默忽略**（用自检脚本的"XPath 能命中"一条排除）；
2. `.cat/.dat` 没重新打包，或没复制到 `extensions/<mod_id>/`；
3. 用的是 `<add>`（追加，1/N 概率）而不是 `<replace>`（整池替换）——
   遇到原版外观是正常的；
4. 游戏没重启 / 扩展没启用；
5. **NPC 外观在实例化时决定**，已在场景里的 NPC 不会立刻变。

## §11.12 改了管线但产物没变

**先查** `05-export-and-packaging.md` §9.3 的三个陷阱（目录已存在 / 删对象无效 /
空槽位不可表达）。这类"静默保留旧产物"的行为最容易浪费一整轮调试。

## §11.13 贴图整体上下颠倒 / 花纹错位（UV 的 v 轴）

**症状**：整张贴图在模型上**上下翻过来**（眼睛长到额头上、衣服图案倒置），
而几何、骨骼、法线、材质全部正常。

**判据**：导入成品 `.xac`，逐网格 dump UV 的 v 范围 ——
**`v_x4` 应等于源 PMX 的 v**（即在 Blender 里读回的是 `1 − v_pmx`）：

```
源 PMX skin      v [0.0615, 0.9263]      ← 目标：xac 里的 v 也是这个值
期望 stage1 存 1−v [0.0737, 0.9385]
导入 xac 后       [0.0737, 0.9385]   ✓
```

**根因**：v 有三层约定、中间差**两次**翻转（PMX 向下 / Blender 向上 /
导出器再翻一次）。stage1 若原样传递 `v_pmx`，X4 拿到的就是 `1 − v_pmx`。

**修法**：stage1 建网格时写入 `1 − v_pmx`（u 不变）。
**不要**去改导出器：它与导入器是对称的一对，改它会同时破坏读取回程。
完整推导见 `01-coordinate-frames.md` §3.6。

## §11.14 衣服上与皮肤同位置的地方有一片片闪烁的黑斑

**症状**：两层几何重叠处出现**随视角闪烁的深色斑块**；静止截图看不出，摄像机一动就跳。

**判据**：`diag_overlays.py` 对每对部件做 KD-tree 最近邻（双向）。两个硬条件 ——
① 分层对的最小距离 ≈ 0（本例 0.00 mm）；② 成对顶点数是数百到数千
（本例 245–3380）→ 确诊。

**根因**：两层几何**位置重合 → 深度相同**，深度缓冲无法稳定判定谁在前。
这不是着色问题，改材质、调颜色都没有用。

**修法**：沿**源顶点法线**把外层整体外推（法线只经旋转，不缩放、不平移）：
`cloth` +2 mm、`elem` +5 mm（量级累加）；`hairspec` **直接丢弃**。
细节见 `04-materials-and-textures.md` §7.7。

**证伪**：外推后重跑 `diag_overlays.py`，最小距离应 ≥ 外推量。
若仍有闪烁，说明还夹着第三层。这是**几何层间距**问题，不要试图用 `TWOSIDED`
或调材质糊过去。

## §11.15 头发 / 衣服从背面看消失，或整体变成黑色

**两条不同的路，先分清**（现象相似，修法相反）：

| 现象 | 根因 | 修法 |
|---|---|---|
| 只在一个方向可见，转到背面**整片消失**（能看到内壳） | 源数据是**单面几何 + 材质标记双面**，X4 默认**剔除背面** | 材质用 `blendmode="TWOSIDED"` |
| 不论从哪看都**整体发黑**，像罩了一层 | 残留的**透明叠加层**被导出器写成不透明 | 构建阶段**丢弃**该叠加层（本例 `hairspec`，见 §11.14） |

**单面那一支的判据**：源侧"双面"只写在材质标记里（本例 20/20 材质 flag bit0 置位），
几何里**没有**任何反向孪生面（22868 面里 0 个）。X4 不读源材质标记，
必须由 mod 侧显式声明。

**不要走的路**：复制一份反向几何当背面层（两层同深度 → 频闪；顶点数翻倍）。
**正解**：`blendmode="TWOSIDED"`，零几何成本；vanilla 先例是
`p1_char_spl_f_cloak_gen_01`（`p1_character` + `TWOSIDED`）。
细节与收益见 `04-materials-and-textures.md` §7.6。

**证伪**：改完必须**回读成品里的 `material_library.xml`** 确认 `TWOSIDED` 真的写进去了
—— 只改构建代码会被导出器的硬编码吃掉（`05-export-and-packaging.md` §9.8）。

## §11.16 遮罩边缘（皮肤 / 镂空处）有一圈深色斑点，远处更明显

**判据**：统计贴图 alpha 分布 + 透明像素的 RGB 均值。`alpha == 0` 的像素 RGB 均值
接近 0 且占比很大 → 确诊（本例 `肌.png` 88% 像素 alpha=0，且这些像素 RGB 是纯黑）。

**根因**：mip 生成对颜色与 alpha **无差别平均**，遮罩边界纹素 = "肤色 + 黑" → 深灰；
同时平均出的 alpha 落在 0.5 之上，alpha test 也剔不掉它。

**修法**：在**生成 mip 之前**把不透明像素的颜色向透明区做形态学扩张（本例 12 圈），
**alpha 保持原样**。见 `04-materials-and-textures.md` §7.8。

**两个容易混淆的点**：

1. **这与"哪些材质需要 alpha 通道"是两件事**。本例只有 `skin` / `elem` 需要 alpha；
   `颜.png` / `髪.png` / `衣.png` 的 alpha 全是 255（几何成形），用 BC1 就够；
2. **判据必须逐面片取**（`diag_alpha_faces.py`）。用顶点级统计会把"落在图集空白区的
   顶点"算成洞，得出"到处都是镂空"的错误结论。

**证伪**：只看第 0 级是证不出来的 —— 要把贴图**降采样到 mip 第 2–3 级**再看遮罩边缘 RGB。

## §11.17 远处的头发 / 布料出现爬动的摩尔纹

**判据**：逐张 DDS 断言 `mipCount == floor(log2(max(w, h))) + 1` 且
`DDSD_MIPMAPCOUNT` 置位（vanilla 对照：2048² → 12 级，256² → 9 级）。

**根因**：DDS **没有 mip 链**，GPU 只能点采样密集图集，在"一个纹素小于一个像素"的
距离上必然走样。

**修法**：BOX 降采样建金字塔，header 置 `DDSD_MIPMAPCOUNT (0x20000)` +
`DDSCAPS_COMPLEX | DDSCAPS_MIPMAP`。字段偏移与坑见 `04-materials-and-textures.md` §7.9。

**证伪**：**拉开距离**看、并让 NPC **走动** —— 静止近看是看不出来的。

## §11.18 关节处断裂 / 台阶 / 缝隙（脚腕、肩臂、手肘）—— **已知问题，未解决**

**症状**：静止时是"台阶"，动画一播变成"撕裂"。

**度量口径**：**边长比 = 结果边长 / 全局拟合边长**（**不要**用"边长 > N × 中位"）。

```
40587 条边：拉伸比中位 1.000，99% 分位 1.966，比值 > 2.0 的 394 条
```

**根因**：源骨架的脊柱骨**几乎重叠**（`下半身` 与 `上半身` 只差 0.7 cm），
X4 的分得很开（`Bip01 Spine` 与 `Spine1` 差 12.8 cm）。蒙皮在两者之间混合 →
跨越两者的边全被撕裂。

**判据很硬**：394 条里 **72 条两端的主导骨是同一根** —— 刚体变换不可能改变距离，
所以拉伸只可能来自"位移不同的骨之间的混合"。

**试过并且无效的**：权重平滑（4 / 10 / 20 / 40 轮结果完全相同）；
给骨链一份共享位移（数字变好，但手臂与脚腕引入更显眼的新弯折 → **全部回退**）。

**当前取舍**：只保留**局部**权重修正；**接受关节残余缝隙**。撕裂的根源是"换骨架的
固有代价"，真正干净的做法是改骨架比例，但那会破坏"骨架必须与 vanilla 逐字节相同"
的硬规则。细节见 `02-retargeting.md` §4.10。

**证伪**：只有两件事算证据 —— ① 边长比 `> 2.0` 的边数下降；
② 实机截图里缝隙变小且**没有引入新的弯折**。

## §11.19 脖子中段有一个折角

**判据**：**按源位置分层**（取源 z 的一个薄层，保证前后量的是同一批顶点），
再看该层在结果里的 x 中心：

```
源 z 148–151 层，源 x 中心 −0.01  →  修复前 +1.60，修复后 −0.00
```

> **按结果 z 分层会选到不同顶点集，数字不可比**（曾因此误判一轮）。

**根因**：颈部下段的原始权重是 `上半身2` 58% + `首` 42%。重定向后
`上半身2 → Spine2` 带 9.9° 拟合旋转、`首 → Neck` 只有 0.3°；颈部距 `Spine2`
枢轴约 26 cm，9.9° 在那个半径上 = 1.6 cm 横向扫掠，而颈部上半段（100% `頭`）
纹丝不动 → 折角。

**关键顺序**：必须在 `transform()` **之前**改**源**权重
（`fix_neck_source_weights()`：把颈部 `|x| < 7`、`z 145–157` 的 `上半身2` 权重转给 `首`）。
第一次在 stage1 里改**最终**权重 —— 它跑了、移动了 674 个顶点、**折角一点没变**，
因为顶点位置是 `transform()` 内部用权重算出来的。

**证伪**：用同一条"源位置分层"口径在修复前后各量一次该层 x 中心（+1.60 → −0.00）。
换一种分层口径量出来的数字**不能**作为证据。

## §11.20 飘带 / 链条被整体抬到不该在的高度

**症状**：飘带、链条、挂饰被整体平移（本例被抬到头顶以上），形状与长度正常 ——
是**整段位移**而不是形变，所以容易被误判成贴图 / 材质问题。

**根因**：**一个 X4 骨只能有一个直接驱动者**。两个源骨写同一个目标骨时，
谁赢取决于**字典遍历顺序**，既不报错也不是"后写的赢"：

```
第一版把 上半身3 与 上半身2 都映射到 Spine2
→ 位置更低的 上半身3 赢了，Spine2 的源位置变成 119.0 而非 ~132
→ 绑在 Spine2 上的顶点被向上平移 13.9 cm
→ 两条飘带（整条 19 节骨链折叠到 Spine2）从肩部被抬到头顶以上
```

**修法**：把 `上半身3` 折叠到它的父骨 `上半身`（→ `Spine1`）；并在映射表完成后、
`transform()` 之前跑 `_assert_unique_targets()` 断言唯一性。
见 `02-retargeting.md` §4.4.1。

**证伪**：量**折叠骨链**（飘带 / 链条 / 裙摆）的 z 范围与 `Head` 的 z 的关系 ——
飘带上端高于 Head 就是错的。不要从形状或材质入手。

## §11.21 衣服上露出本该看不见的内衬 / 身体色块 / 硬边黑块

**症状**：衣服外面浮出**里子**、被衣服盖住的身体（胸口一块、腋下两块），
或者一片边缘生硬的深色块；同时（或换个角度看）**裙摆、袖子从内侧穿帮**。
两种现象一起出现时最容易被当成两个 bug。

**根因**：X4 的 `blendmode` 是**单值**，`TWOSIDED` 与 `ALPHA1/ALPHA8` 不能兼得。
MMD 作者用"贴图 alpha 涂 0"隐藏不要的面，而这些面**在几何里仍然存在**：
选了 `TWOSIDED` → 忽略 alpha，**变成实心**；选了 alpha → **背面被剔除**。

**判据**：按三角形三个顶点的 UV 采样贴图 alpha，**均值 < 0.03 的就是"隐藏面"**。
实测（甘雨）：`cloth` 906/9944（胸衣内衬）、`skin` 86/1086（被衣服盖住的身体）。

**修法**：构建时**删掉这些三角形**（`keep = alpha >= 0.03`），材质于是可以统一走
`TWOSIDED`，贴图也能从 BC3 降到 BC1。见 `04-materials-and-textures.md` §7.11。

> ⚠️ 删之前把"要删的"和"要留的"**分组渲染出来看**：前者是成片的面板（删了无感），
> 后者若是沿轮廓的羽化边，删了会啃掉剪影。**这个分类的代价不对称，必须看图。**

**证伪**：删掉的面数应与诊断脚本的预期**逐材质对上**（对不上说明构建与诊断用的不是
同一份采样实现）；删完再查材质 manifest —— 若 `cloth`/`skin` 仍挂着 alpha 标记，
说明有面没删干净。
