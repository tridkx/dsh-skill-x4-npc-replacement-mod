# §5 减面与顶点预算 / §6 法线与切线

## §5 顶点预算：X4 会因超预算**频闪**

### §5.1 症状与量级

X4 的 NPC 是**实例化渲染**的（空间站里同时几十个），而地图界面要绘制全部已知
对象。资产超预算时最先崩的是显存：

| 症状 | 说明 |
|---|---|
| 空间站内**频闪** | 最先出现 |
| **地图卡死** | 同时绘制全部对象 |
| 地图出现**彩色斑块** | 显存数据损坏 |

**实测量级**（本例，两个资产合计）：

| 版本 | 导出顶点 | 相对 vanilla | 结果 |
|---|---|---|---|
| 未处理 | ~700k | 73× | 频闪 / 地图卡死 |
| 早期稳定版 | ~75k | 9× | 稳定 |
| 追求细节版 | 129k | 15.5× | **频闪复发** |
| 终版 | ~52k | **6.3×** | 稳定 |

**口径**：导出器的顶点计数**含每条 UV 接缝与法线接缝**，
所以比较时必须用"导出后的顶点数"，不能用 Blender 里的原始网格顶点数。

### §5.2 减面比例

```python
DECIMATE_RATIO = {
    'hair':   0.10,
    'jacket': 0.35,
    'body':   0.30,
    'slingbelt': 0.70,
    'hand_l': 1.00,   # 手部一点不减，见 §6.3
    'hand_r': 1.00,
    'eyes':   0.50,
    'face':   0.50,
}
```

**两条经验**：

1. **比例与最终顶点数不是线性的** —— 小网格会撞到"减完不足 N 顶点则回退原网格"
   的下限，所以实际保留量往往远高于 ratio。**要跑一次量出来，别算**。
2. **薄壳/长条部位（手指、挎带）掉得最快**。挎带只占总量极小，
   比例给到 0.6~0.7 几乎不增加预算，但形状能保住。

### §5.3 边界保护：一次失败的尝试（**别重蹈**）

想法很合理：collapse 减面会吃掉衣摆、鞋帮、腰带的外轮廓，于是给"边界顶点"
高权重让减面器绕开它们。

**实测结果：顶点数从 4k 跳到 20k**（比例 0.09 却保留 68%）。原因：

```
源资产里有"卡片几何" —— 成堆互不相连的四边形：
  jacket 的缝线层  faces/vertex ≈ 1.0，84–87% 顶点在边界上
  jacket 的金属件  faces/vertex ≈ 1.04，84% 边界
标它们"受保护" = 标了几乎全部顶点 = 减面完全关闭
```

**结论**：这类启发式对**碎片化网格**会失效，而碎片化在角色资产里很常见。
**宁可要可预测的纯 ratio，也不要不可预测的"聪明"保护**。
（如果确实要保护，判据是"边界顶点占比 < 50%"才启用。）

## §6 法线与切线

### §6.1 面片感的真凶是法线，不是面数

**症状**：脸上、身上有明显的三角面片，看起来"粗糙"。

**排查**：导入成品 `.xac`，量 `|顶点法线 − 面法线|`：

```
平光着色：0.000   ← 每个三角形带自己的面法线
平滑着色：0.4 左右
```

**成因**（两段式管线各一半）：

```
stage1 建网格 → 设了 use_smooth ✓
stage2 用 from_pydata 重建网格 → 默认回到平面着色 ✗
导出器读的是 loop.normal → 面法线进了 .xac ✗
```

**修法：两个阶段都要设**：

```python
for poly in mesh.polygons:
    poly.use_smooth = True
```

### §6.2 顺带的大收益：法线接缝

X4 的导出计数**每个 UV 接缝和法线接缝各算一个顶点**。平滑法线消掉法线接缝：

```
导出顶点  45 189 → 13 355   （−70%）
```

**所以"法线"和"减面"是同一笔预算的两种花法**，而前者免费且直接改善观感。
终版用这笔预算把面数提到上一版的 **2.3 倍**，同时导出顶点**更少**。

### §6.3 切线跟着 UV：**手部不要减面**

**症状**：手指上有一圈圈**横向环纹**，指根有深色斑块。
（workbench 预览**看不到** —— 它不显示法线贴图；必须用 EEVEE/Cycles 复现。）

**成因**：切线是按 UV 推的。collapse 重写手指那点 UV，切线空间随之错乱，
法线贴图渲染成环纹。

**修法**：

```python
'hand_l': 1.00, 'hand_r': 1.00     # 手部本来只有 2346 顶点/只，不减
# 同时手部跳过权重平滑：权重已均匀，扰动顶点只会继续糟蹋法线贴图
if tag not in ('hand_l', 'hand_r'):
    smooth_vertex_weights(ob)
```

**可推广的结论**：**只要材质带法线贴图，减面就不只是几何问题**。
脸、手这类"有细节贴图又在近景"的部位，代价要按**切线质量**算，不能只按顶点数算。
（本例终版脸给了 0.50 —— 脸上的法线贴图同样敏感，若还有粗糙感可继续往上调。）

### §6.4 用 EEVEE 复现实机观感

workbench 只看几何与固有色，**法线贴图、粗糙度、透明全都不显示**。
凡"实机看到的纹路/斑块"类问题，一律用 EEVEE 渲染复现：

```python
scn.render.engine = 'BLENDER_EEVEE'      # Blender 5.2 没有 EEVEE_NEXT 这个枚举
world.node_tree.nodes["Background"].inputs[0].default_value = (0.35, 0.35, 0.38, 1)
# 加两三个点光，energy 要很大（厘米量纲）：4e6 量级
```
