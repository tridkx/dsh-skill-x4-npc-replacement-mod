## §2 三个坐标系

| 空间 | 排列 | 单位 | 证据（怎么量的） |
|---|---|---|---|
| 源（本例 RE8） | `(x, up, forward)` | 米 | 骨架 JSON 的 worldMatrix 平移 |
| X4 `.xac` / Blender | `(x, forward, up)` | 厘米 | `Bip01 Head` z=161.4；`left_eye_dummy` y=+4.8 |
| 导出器内部 | — | — | 插件自己做一次坐标搬运，**不要重复搬** |

**映射**：

```python
def source_to_x4(p_m):        # 源（米）→ X4/Blender（厘米）
    return (p[0] * 100.0, p[2] * 100.0, p[1] * 100.0)   # (x, z, y)，注意 y/z 互换
```

**怎么确认源空间的哪个轴是"前"**（不要猜）：

```python
# 拿两个必然有前后语义的部位比：
#   眼球几何重心 vs 头骨；脚趾 vs 脚踝
# 眼球/脚趾所在的那一侧就是「前」
Rose: 眼球网格重心在 Head 骨的 +z 侧（+4.9 cm）  → 源空间 +z = 前
X4  : ter_eyeball_left 在 Bip01 Head 的 +y 侧（+9.5 cm） → X4 +y = 前
∴ z 必须映射到 +y，不能取负
```

## §3 手性、反射与绕序（**必读**）

### §3.1 为什么符号错了拟合不会报警

`(x, z, y)` 与 `(x, −z, y)` 只差一个符号，但：

| 映射 | 行列式 | 后果 |
|---|---|---|
| `(x, z, y)` | **−1（反射）** | 顶点位置**物理正确**，但三角形绕序翻转 |
| `(x, −z, y)` | +1（保向） | 绕序正常，但顶点位置**前后镜像** |

**两个都不能直接用**，正确做法是：

```
用 (x, z, y)（物理正确）+ 建网格时把每个三角形反过来
```

### §3.2 错误 A：写成 `(x, −z, y)`（前后镜像）—— 最具迷惑性

角色前后镜像。而**镜像是一种反射，只用旋转的 Kabsch 拟合永远修不回来**
（Kabsch 强制 `det(R)=+1`），于是拟合退而求其次给出"最优旋转"，
残差全部堆在**前后方向偏离最大的部位**：

```
手指 57.8 cm   手 42.0 cm   脚趾 23.4 cm     ← 前后偏离大
躯干 1–10 cm   头 2.8 cm                      ← 近似对称，几乎不受影响
```

**这个分布会被误读成"姿态差异"**，进而走上"旋转手臂顶点"的局部 hack 死路。
判据是**解剖学方向**，不是拟合残差：

```
用 (x, z, y) 重拟合同一批骨对：
手指 28.6 / 手 25.3 / 脚趾 10.6 cm   ← 残差减半，且剩下的是真实比例差异
```

### §3.3 错误 B：用了 `(x, z, y)` 但没反转绕序

顶点位置看着完全正确（指标、骨骼叠加图、包围盒都过），但**每个三角形都朝内**：

| 实机症状 | 机制 |
|---|---|
| 衣裤鞋**透明**、能看到对面内壳 | 引擎剔除正面，只看到背面 |
| 光照错乱、布料像**揉皱的破布** | 法线朝内，光照方向反了 |
| **脸整片消失** | 同上，面片被剔除 |
| 手/脚看起来"还行" | 那些部位本来就有双面感，掩盖了问题 |

**修法**：

```python
# 建网格时把三角形反过来
faces_local = [tuple(remap[i] for i in reversed(f)) for f in faces]
```

UV **不受影响**：UV 是逐顶点（或逐 loop、按 `vertex_index` 取）带过去的，
反转顶点顺序不会改变某个顶点对应的 UV。但**如果你是按 loop 顺序展开 UV 数组的，
反转面时要保证 UV 数组也跟着同一个顺序**。

### §3.4 判据：`check_normals.py`

逐网格统计"面法线是否背离质心"的比例：

```python
self.diffuse_color ...  # 不相关
ratio = (dot(face_center - mesh_centroid, face_normal) > 0).mean()
```

| 值 | 含义 |
|---|---|
| 0.55 – 0.85 | healthy（凹形状如手指间隙会低一些） |
| < 0.5 | **绕序翻转**（精确翻转 = 1 − 原值，实测 0.435 → 0.565） |
| 恰好 0.5 | 高度可疑，看具体网格 |

**先用原版资产标定阈值**：vanilla 里最凹的网格（Sneakers 0.593、Hands 0.613）
决定了健康下限。本例阈值取 0.45。

> **这个检查不能省**：本例绕序错误在实机表现为"三个新问题"，而所有基于
> 顶点位置的检查（指标、包围盒、骨骼叠加）**全部显示正常**。
> 直到打开背面剔除渲染 + 染色定位才看清。

### §3.5 验证用的两个渲染设置

```python
# 1) 关掉双面渲染，复现实机的背面剔除
scn.display.shading.show_backface_culling = True

# 2) 平光 + 材质色，用来定位"哪块几何属于哪个材质"
scn.display.shading.color_type = 'MATERIAL'
mesh_obj.data.materials[i].diffuse_color = (1, 0, 0, 1)   # workbench 读这个，不是节点颜色
```

> 踩坑：`scn.display.shading.color_type = 'MATERIAL'` 读的是
> **`material.diffuse_color`**，不是 Principled BSDF 的 Base Color。
> 只改节点颜色，渲染出来仍是灰的。
