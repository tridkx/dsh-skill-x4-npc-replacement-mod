# §4 重定向：把网格搬到 X4 的绑定姿态

> X4 的动画是**相对绑定姿态**的旋转。蒙皮定义在绑定姿态上，所以**顶点在绑定
> 姿态下必须落在它主导骨附近** —— 否则动画一播，那些顶点就被甩向错误方向
> （实机症状："动作时四肢朝反向弯、手指被拉长"）。

## §4.1 为什么一次刚体变换必然失败

先做一次全局 Kabsch / SVD 拟合（用 18 对无歧义骨对）是对的，但**只能做粗对齐**：

```
scale = 1.047   det(R) = +1
残差：Head 2.8 / Hip 9.8 / 手 25.3 / 脚趾 10.6 cm
```

手和脚的残差不是"没拟合好"，而是**两套骨架的姿态与比例真的不同**：

| 段 | 源 | X4 Biped | 差 |
|---|---|---|---|
| 骨盆 → 肩 | 37.1 cm | 52.3 cm | +15 cm |
| 肩 → 腕（骨链） | 45.9 cm | 59.2 cm | +13 cm |
| 手方向 | 前伸下垂 | 自然下垂 | ≈ 95° |
| 踝 → 趾落差 | 6.3 cm | 11.4 cm | 近一倍 |
| 脖子长（Neck→Head） | 13.7 cm | 7.8 cm | 近一倍 |

**结论**：不能靠一个变换；要**逐骨**把几何搬到目标姿态。
（本例曾用"绕肩旋转手臂顶点"这类局部 hack 去救，结果把整体误差从 20.6 推到
21.7 —— 那是死路。）

## §4.2 逐骨绑定姿态转移（核心算法）

对**每一根 X4 骨 B**（有源骨对应）构造一个刚体变换：

```
x  →  q_B + R_B · (x − p_b)
```

- `p_b` = 对应源骨在全局框架拟合后的位置
- `q_B` = X4 骨在绑定姿态的位置（`head`）
- `R_B` = 把**源骨轴**旋到**目标骨轴**的最短弧旋转（`min_rotation`）

顶点位移 = **按蒙皮权重混合**：

```
v' = Σ w_B · T_B(v) / Σ w_B        （等价于在转换期做一次 LBS）
```

**骨架一个字节都不动** ✓ 权重骨名不变 ✓ 材质槽不变 ✓

### §4.2.1 `min_rotation` 的 180° 陷阱

两向量恰好反向时（s ≈ 0），**绝不能返回 `-I`** —— 那是反射不是旋转：

```python
if s < 1e-9:
    if c > 0: return np.eye(3)
    t = np.array([1.0, 0, 0]) if abs(a[0]) <= 0.9 else np.array([0, 1.0, 0])
    k = np.cross(a, t); k /= np.linalg.norm(k)
    return 2.0 * np.outer(k, k) - np.eye(3)      # 绕任意垂直轴转 180°
```

## §4.3 骨轴推导：**只能用主链第一个子骨**

### §4.3.1 不要读骨骼矩阵的行

源骨架里**没有统一的局部轴约定**。本例 Rose 的骨架：脊柱的骨轴落在矩阵
**第 0 行**，上臂的也在第 0 行 —— 但直接把行当骨轴，脊柱恰好差 90°、
左手手指差 168–172°，而右手对应骨只差 8–12°。**左右不对称就是信号**。

### §4.3.2 也不要取子骨均值

```
骨轴 = 子骨位置均值 − 自身位置        ← 在分叉骨上会给出与解剖学无关的方向
```

实例：Rose 的 `Hip` 有三根子骨 —— `Spine_0`（与它**完全重合**）和左右大腿
（朝**下**），均值朝下；而 X4 的 `Bip01 Pelvis` 指向 `Spine`（朝**上**）。
拟合出 **161° 骨盆旋转**，把所有权重落在骨盆上的顶点（夹克下摆、裤腰、鞋帮）
整体转翻 —— 实机症状是"腰部一块浅褐色补丁、颜色与原版对不上"。

### §4.3.3 正确做法

```python
def pair_axis(bone, B):
    """源/目标骨轴：只看主链第一个子骨；退化时退到父骨方向；再不行不旋转。"""
    # 1) 主链第一个子骨（骨架顺序里的第一个），且距离足够
    for c in children[bone]:
        d = src[c] - src[bone]
        if norm(d) < MIN_AXIS_LEN:      # 例如 2 cm
            break                        # 主链退化，别去看别的子骨
        other = map_bone(c)
        if other in x4 and other != B:
            return normalize(d), normalize(x4[other].head - x4[B].head)
        break
    # 2) 父骨方向（注意：父骨给的是「入射方向」，要取反）
    par = parent[bone]
    if par:
        d = src[bone] - src[par]
        v = normalize(x4[map_bone(par)].head - x4[B].head)
        return normalize(d), -v
    # 3) 无方向可用：不旋转（而不是编一个 180°）
    return None, None
```

**自检**：绝大多数骨的旋转量应 < 60°；出现干净的 90° / 180° 基本就是推导错了。

```
骨盆 161.3°  ← 错
其余最大 46.5°（手指/前臂，属真实姿态差异）  ← 对
```

## §4.4 折叠骨：必须锚定，不能各自对齐

**折叠骨** = 在目标骨架里**没有位置对应**、只是"共用"某根骨的源骨。
典型命名：`jacket_*`、`Hair*_FK_*`、`*_Twist_*`、`*_muscle`、`FACIAL_*`、
`eyelid/eyebrow/lip`。

**如果给它们"目标骨位置 − 自身位置"的位移**：夹克会被推进胸腔（实测差 30 cm）。

**正确做法**：继承**同侧最近的那根"有对应关系的骨"**的变换。

```python
DIRECT_BONES = {...}      # 显式列出有一对一语义对应的骨
def anchor(b):
    if b in DIRECT_BONES: return b
    side = 'L' if b.startswith('L_') else 'R' if b.startswith('R_') else None
    return min((c for c in DIRECT_BONES
                if not side or c.startswith(side + '_')),
               key=lambda c: norm(src[b] - src[c]))
```

**顺带一个映射 bug 类型**：折叠骨的命名下标语义要实测。
本例 `jacket_<N>_<M>` 里 **N 是绕身角度、M 才是沿链向下的高度**
（每条链都挂在 `Spine_2`，`M=0` 在 z≈127、`M=3` 在 z≈100）。
按 N 映射 = 把下摆绑到脖子。

## §4.5 手指：绑到手掌（**用形状换动画**）

**问题**：源角色手指**并拢**、X4 手指骨**张开**。逐骨对齐 = 把手掰开，
而**指间的皮（虎口、指蹼）本身没有几何**，只是两侧皮肤连起来的过渡 —— 一掰就撕开，
实机症状是"虎口像平白少了一块皮"。

**三种做法实测**：

| 做法 | 静态手型 | 动画 |
|---|---|---|
| 手指绑各自骨 | 指间裂到掌根 ✗ | 正常 |
| 半量混合（各 50%） | **五根手指各自扭曲**（最差）✗ | 差 |
| **手指绑手掌（推荐）** | **与原作者手型一致** ✓ | 手指不单独弯曲 |

```python
FINGERS_BIND_TO_PALM = True
# 合并权重时：Bip01 {L,R} Finger* → Bip01 {L,R} Hand
```

**注意**：半量混合是**错的**方向 —— 每根手指的混合结果都不同，反而把五根手指
全部扭了。要么全跟骨骼、要么全跟手掌，**不要取中间**。

## §4.6 脚：共用位移 + 地面双向对齐

**症状**：脚跟离地、只有前掌着地。**实测高度分布**：

```
             脚跟    足弓    前掌    脚趾
vanilla     -0.15   -0.25   -0.32    1.10     ← 整个鞋底贴地
逐骨各自    5.43    3.23   -0.48   -0.59     ← 只有前掌着地
```

**真凶不是旋转而是位移差**：X4 的 `Toe0` 目标比源脚趾骨**低 3.1 cm**，
而 `Foot` 目标**高 2.0 cm**，逐骨各走各的把脚撬斜了。

```python
# 1) 整只脚共用踝关节的位移（脚本来就是刚体）
for side in ('L', 'R'):
    d = delta['Bip01 %s Foot' % side].offset
    for suffix in ('Foot', 'Toe0', 'Toe0Nub'):
        delta['Bip01 %s %s' % (side, suffix)] = src + d
# 2) 脚部顶点（Foot/Toe 权重 > 0.5）对齐到地面 —— 双向！
dz = GROUND_Z - verts[mask][:, 2].min()      # GROUND_Z ≈ -0.5
if abs(dz) > 0.05: verts[mask, 2] += dz      # 不要只在 dz>0 时抬
```

> 注意 `_MIN_AXIS_LEN` 之类的判据：`lift_feet` 的 mask **不要包含 Calf 权重**，
> 否则小腿会跟着被抬起来。

修完：`-0.49 / -0.30 / -0.27 / 0.77`，与 vanilla 齐平。

## §4.7 眼球：两个独立 bug

**(a) 几何放错**：`ch01_6030_rose_eyes` **不是眼球** —— 它是 `shader_eyes_shader`，
高度 y 1.542–1.570；而 `face` 部件里的 `Eye_Mat` 在 y 1.584–1.611，
**正好与眼睑(1.584–1.602)、睫毛对齐**。
即前者是一个**低了 4.2 cm 的拷贝**。**先量源数据的各子网格高度分布再决定用哪个**。

**(b) look-at 甩飞**：X4 用 look-at 控制器驱动 `left/right_eye_dummy`，
而源眼球几何离这两根骨约 9 cm（X4 的 eye_dummy 在 `Bip01 Head` **上方 8.5 cm**，
源的在 Head **下方**）。视线一转眼球就绕 9 cm 半径甩出去 —— 实机症状
"眼球大部分时候正常、偶尔错位不跟头"。**修法：这两根骨上的权重改挂 `Bip01 Head`。**

**另外**：如果源眼球**绑到头部变换**，会与脸对齐但离 eye_dummy 骨 9 cm；
这比"跟着 look-at 飞出去"好 —— **稳定优先**。

## §4.8 头颈：共用位移（解决"缩在衣领里"）

**量**：源数据里**眼球比夹克领口高 7.5 cm**，vanilla 9.9 cm，逐骨各自对齐后只剩 **0.6 cm**。

**原因**：X4 的 `Head` 只比 `Neck` 高 7.8 cm，源的高 13.7 cm。各自对齐 →
头被拽下 5.9 cm、领口被推上 → 两头一挤就缩进去了。

```python
shared = 0.5 * (d_neck + d_head)      # 取两根骨位移的平均
delta['Bip01 Neck'] = (src_neck, src_neck + shared, R_neck)
delta['Bip01 Head'] = (src_head, src_head + shared, R_head)
```

各骨离自己的目标约 3 cm，但作者设定的头颈间距保住了。修完脸顶从 177.5 → 180.9 cm。

> **顺序很重要**：先做头颈调和，**再**让眼球骑头部变换，否则眼球用的是未调和的头变换。
