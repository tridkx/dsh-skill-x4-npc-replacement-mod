# §10 验证：工具与发版清单

> **验证纪律**（三条，比工具更重要）：
>
> 1. **改一处、重跑管线、再看结果**。导出器会静默失败/静默保留旧产物（§9.3），
>    对着旧文件调试是最常见的浪费。
> 2. **每个结论都要有"能一眼看错"的判据**。本例的"骨骼叠加渲染"和"指标表"
>    比任何推理都可靠；而中途多个诊断脚本自己把坐标系混着比，把人带偏了好几轮。
> 3. **先证伪自己的假设**。例如"残差集中在四肢 = 姿态差异"这个判断，
>    只要做一次"把前后轴取反再拟合"的对照实验就会被推翻。

## §10.1 四个判据工具

| 工具 | 判据 | 通过标准 |
|---|---|---|
| `xac.py` `compare_skeletons()` | 骨骼名顺序 + bind payload **逐字节** | 名一致 + 91/91 相同 |
| `check_normals.py` | 逐网格"面法线背离质心"比例 | ≥ 0.45（vanilla 最凹网格 0.59） |
| `dbg_normals.py`（导入成品后自检） | `\|顶点法线 − 面法线\|` | ≈ 0.4（0.000 = 平面着色，错） |
| `eval_skin.py` | 每顶点到其主导骨**线段**的平均距离，按部位分组 | 与 vanilla 同口径对比 |

### §10.1.1 绑定质量指标的口径（关键）

```
指标 = 顶点到「主导骨线段」的距离（不是到骨骼点的距离）
```

- 必须**按部位分组**看（手指/手掌/前臂/上臂/大腿/小腿/脚/脚趾/躯干/锁骨）
- 必须**与 vanilla 同口径**对比（用同一条导入链 dump 出来再算）
- **衣服/头发的躯干值天然偏大**（几何在体外），不要拿它当失败

实测参考（厘米，均值）：

| 部位 | 源数据原生 | vanilla | 成品 |
|---|---|---|---|
| 手指 | — | 1.11 | 0.96 |
| 脚趾 | — | 4.36 | 5.79 |
| 手掌 | — | 5.34 | 5.16 |
| 上臂 | — | 6.93 | 6.5 |
| 大腿 | — | 6.86 | 7.4 |
| 总体 | — | 7.17 | ~10（夹克顶点多，把均值拉高） |

**注意**：脚趾 5.79 是"脚部共用位移"取舍的代价（§4.6），不是 bug。

## §10.2 视觉判据（比数字更能说明问题）

```python
# 1) 骨骼叠加：把骨骼画成小方块叠在网格上，看是否落在肢体内部
#    —— 这是最可靠的单一检查
# 2) 姿态测试：绕关节旋转（肘/膝/走/扭腰），渲染后与 vanilla 并排
# 3) 背面剔除开启 + 正面视图：查绕序（脸/衣服）
# 4) EEVEE + 法线贴图：查法线/切线类问题（workbench 看不到）
# 5) 源网格直渲（不重定向不减面）：作为"管线是否引入问题"的基准
```

**第 5 条特别有用**：任何"看起来不对"的部位，都把源网格单独渲染一遍。
如果源网格也那样，那是数据固有/着色器差异；如果源网格正常而成品不对，
就是管线的问题。本例靠它把"眼睛错位""腰部补丁"两次定位到具体环节。

## §10.3 发版前自检清单

写成脚本（`verify_mod.py`）一次跑完，任何一条不过就不发版：

```
[ ] content.xml / charactergroups.xml / character_macros.xml /
    material_library.xml 都是 well-formed XML
[ ] 每个 diff 的 sel= XPath 在原版库里**能命中节点**
    （写错的 XPath 游戏会静默忽略）
[ ] 应用 diff 后，每个目标外观池**只解析到本 mod 的 macro**（若用了全替换模式）
[ ] macro 继承的 ref macro、引用的 component 在原版里存在
[ ] macro 的每个 model ref 指向的 .xac 真实存在
[ ] 两份 .xac 的骨架与 vanilla **逐字节相同**
[ ] 贴图数量 > 0，且 material_library 里每个贴图路径都能在 mod 内解析到
[ ] check_normals 通过
[ ] 导入成品 .xac 不报错（退化三角形/无权重顶点会在这一步暴露）
[ ] 顶点总数在预算内（本例 ~6× vanilla）
```

**其中"XPath 能命中"这条最容易漏**：`sel=` 写错时游戏不报错、只是那条改动
不生效，表现为"改了 XML 但游戏里没变化"。

> 写自检脚本时注意：**XPath 的根节点是文档元素本身**。
> `/characters/character[@name='x']` 里的第一个 `characters` 对应
> ElementTree 的 root，而不是 root 的子节点 —— 按后者写会全部匹配 0 个。
