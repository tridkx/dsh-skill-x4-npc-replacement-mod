# §10 验证：工具与发版清单

> **验证纪律**（三条，比工具更重要）：
>
> 1. **改一处、重跑管线、再看结果**。导出器会静默失败/静默保留旧产物（§9.3），
>    对着旧文件调试是最常见的浪费。
> 2. **每个结论都要有"能一眼看错"的判据**。本例的"骨骼叠加渲染"和"指标表"
>    比任何推理都可靠；而中途多个诊断脚本自己把坐标系混着比，把人带偏了好几轮。
> 3. **先证伪自己的假设**。例如"残差集中在四肢 = 姿态差异"这个判断，
>    只要做一次"把前后轴取反再拟合"的对照实验就会被推翻。

## §10.1 四个判据工具

| 工具 | 判据 | 通过标准 |
|---|---|---|
| `xac.py` `compare_skeletons()` | 骨骼名顺序 + bind payload **逐字节** | 名一致 + 91/91 相同 |
| `check_normals.py` | 逐网格"面法线背离质心"比例 | ≥ 0.45（vanilla 最凹网格 0.59） |
| `dbg_normals.py`（导入成品后自检） | `\|顶点法线 − 面法线\|` | ≈ 0.4（0.000 = 平面着色，错） |
| `eval_skin.py` | 每顶点到其主导骨**线段**的平均距离，按部位分组 | 与 vanilla 同口径对比 |

### §10.1.1 绑定质量指标的口径（关键）

```
指标 = 顶点到「主导骨线段」的距离（不是到骨骼点的距离）
```

- 必须**按部位分组**看（手指/手掌/前臂/上臂/大腿/小腿/脚/脚趾/躯干/锁骨）
- 必须**与 vanilla 同口径**对比（用同一条导入链 dump 出来再算）
- **衣服/头发的躯干值天然偏大**（几何在体外），不要拿它当失败

实测参考（厘米，均值）：

| 部位 | 源数据原生 | vanilla | 成品 |
|---|---|---|---|
| 手指 | — | 1.11 | 0.96 |
| 脚趾 | — | 4.36 | 5.79 |
| 手掌 | — | 5.34 | 5.16 |
| 上臂 | — | 6.93 | 6.5 |
| 大腿 | — | 6.86 | 7.4 |
| 总体 | — | 7.17 | ~10（夹克顶点多，把均值拉高） |

**注意**：脚趾 5.79 是"脚部共用位移"取舍的代价（§4.6），不是 bug。

### §10.1.2 资产完整性检查（每条都给判据与阈值）

| 检查 | 判据 | 阈值 / 通过标准 | 不过的后果 |
|---|---|---|---|
| **贴图朝向** | 导入成品 `.xac`，逐网格 dump UV 的 v 范围，与源 PMX 比 | `v_x4 == v_pmx`，即导入回 Blender 的 v == `1 − v_pmx` | 整张贴图上下颠倒（§11.13） |
| **mip 链完整性** | 逐张 DDS 读 header：`mipCount` + `DDSD_MIPMAPCOUNT` | `mipCount == floor(log2(max(w, h))) + 1` 且标志位置位 | 远处发丝/织纹摩尔纹（§11.17） |
| **重合层** | `diag_overlays.py`，逐部件对做 KD-tree 最近邻（双向） | 每对最小距离 ≥ 外推量（本例 cloth +2 mm / elem +5 mm） | 同深度闪烁黑斑（§11.14） |
| **关节撕裂** | **边长比 = 结果边长 / 全局拟合边长** | 统计比值 `> 2.0` 的边数（本例 40587 条中 394 条） | 关节缝隙（§11.18，已知问题） |
| **贴图颜色渗漏** | 遮罩边缘的低 alpha 像素 RGB 是否已被扩张 | `alpha == 0` 区域的 RGB 均值应远离 0（不再纯黑） | 遮罩边缘一圈深色斑点（§11.16） |

**贴图朝向的验证链**（可复现；v 轴的三层约定见 §11.13）：

```
源 PMX skin              v [0.0615, 0.9263]      ← 目标：xac 里的 v 也是这个值
期望 stage1 存 1−v        [0.0737, 0.9385]        （导出器 addon.py:855 会翻一次）
导入 xac 回 Blender 实测   [0.0737, 0.9385]
  → v_x4 = 1 − [0.0737, 0.9385] = [0.0615, 0.9263]  ✓
```

**mip 链的对照值**（vanilla 每一张都有完整链）：

```
char_ter_f_afr_blend_head_01_diffhq    2048²   mipCount = 12
其 -small 变体                          256²   mipCount = 9
```

**关节撕裂的度量口径**：只认**边长比**。

```
40587 条边：比值中位 1.000，99% 分位 1.966，> 2.0 的 394 条
```

**不要**用"边长 > N × 中位"：那抓到的是模型本来就有的长结构边
（源长 9.3 cm 的边结果也是 9.3 cm，比值 1.000，却会被判成异常）。
本例 394 条里有 **72 条两端主导骨是同一根** —— 刚体变换不可能改变距离，
这类边只可能来自"位移不同的骨之间的混合"。

## §10.2 视觉判据（比数字更能说明问题）

```python
# 1) 骨骼叠加：把骨骼画成小方块叠在网格上，看是否落在肢体内部
#    —— 这是最可靠的单一检查
# 2) 姿态测试：绕关节旋转（肘/膝/走/扭腰），渲染后与 vanilla 并排
# 3) 背面剔除开启 + 正面视图：查绕序（脸/衣服）
# 4) EEVEE + 法线贴图：查法线/切线类问题（workbench 看不到）
# 5) 源网格直渲（不重定向不减面）：作为"管线是否引入问题"的基准
```

**第 5 条特别有用**：任何"看起来不对"的部位，都把源网格单独渲染一遍。
如果源网格也那样，那是数据固有/着色器差异；如果源网格正常而成品不对，
就是管线的问题。本例靠它把"眼睛错位""腰部补丁"两次定位到具体环节。

## §10.3 发版前自检清单

写成脚本（`verify_mod.py`）一次跑完，任何一条不过就不发版：

```
[ ] content.xml / charactergroups.xml / character_macros.xml /
    material_library.xml 都是 well-formed XML
[ ] 每个 diff 的 sel= XPath 在原版库里**能命中节点**
    （写错的 XPath 游戏会静默忽略）
[ ] 应用 diff 后，每个目标外观池**只解析到本 mod 的 macro**（若用了全替换模式）
[ ] macro 继承的 ref macro、引用的 component 在原版里存在
[ ] macro 的每个 model ref 指向的 .xac 真实存在
[ ] 两份 .xac 的骨架与 vanilla **逐字节相同**
[ ] 贴图数量 > 0，且 material_library 里每个贴图路径都能在 mod 内解析到
[ ] check_normals 通过
[ ] 导入成品 .xac 不报错（退化三角形/无权重顶点会在这一步暴露）
[ ] 顶点总数在预算内（本例 ~6× vanilla）
```

**其中"XPath 能命中"这条最容易漏**：`sel=` 写错时游戏不报错、只是那条改动
不生效，表现为"改了 XML 但游戏里没变化"。

> 写自检脚本时注意：**XPath 的根节点是文档元素本身**。
> `/characters/character[@name='x']` 里的第一个 `characters` 对应
> ElementTree 的 root，而不是 root 的子节点 —— 按后者写会全部匹配 0 个。

### §10.3.1 追加到 `verify_mod.py` 的必跑项（本轮新增）

```
[ ] 成品 xac 的 UV v 范围 == 1 −（源 PMX 的 v 范围），并导入回 Blender 复核
[ ] 逐张 DDS：mipCount == floor(log2(max(w,h))) + 1，且 DDSD_MIPMAPCOUNT 置位
[ ] 逐材质断言 material_library.xml 的 shader / blendmode 与 manifest 一致
    （导出器这两个字段是硬编码的，见 §9.8 —— 不查这条等于所有材质设置存疑）
[ ] 重合层：diag_overlays.py 每个分层对的最小距离 >= 该层的外推量
[ ] 需要 alpha 的材质集合与实测一致（diag_alpha_faces.py，逐面片取自己 UV 的 alpha）
[ ] 贴图渗漏：alpha == 0 区域的 RGB 已扩张（不再是纯黑）
[ ] 目标 macro 集合 = 有效 race/female/faction 判据 并集 目标池选中
    （池要递归展开 <select character=...> 间接链接；这条曾抓出 2 个漏网外交官 macro）
[ ] 边长比 > 2.0 的边数已记录（已知问题，只作回归对比，不作为发版通过条件）
```

### §10.3.2 **发版之后**的必做项（不是检查产物，是检查"装上了没有"）

```bash
# 1) 游戏里那份的实际版本 —— 这一条曾让 20 多轮诊断全部白做
grep -o 'version="[0-9]*"' "…/X4 Foundations/extensions/<mod_id>/content.xml"
# 2) 有没有旧目录/备份目录并存（同 id 会冲突）
ls "…/X4 Foundations/extensions/" | grep <mod_id>
```

```
[ ] content.xml 的 version 与本次发布版本一致（version="140" = v1.4）
[ ] extensions/ 下只有**一个** <mod_id> 目录（备份目录在确认无误后删掉）
[ ] 用户已**重启游戏**（X4 只在启动时读 extensions）
```

> **本项目最贵的流程漏洞**：连着二十多轮离线诊断，一次都没核对过游戏里
> `extensions/x4_lumine_mod/content.xml` 的 `version` —— 实际装着的是三周前的
> v1.0，从 v1.2 起的每一步修复都没生效，用户说的"没用"其实是在描述初版。
>
> **"我修好了"和"用户看到的是修好的版本"是两件事。** 报"已修复"之前跑一遍上面
> 三条；顺手把 `version` 跟着发布版本号走，用户就能在游戏扩展菜单里自己确认。

**前两条（v 范围、mipCount）是本轮才补上的**：它们对应的症状在软渲染预览里
**不可能复现**（预览走源 PMX 的 UV、通常只采 mip 第 0 级），
所以必须靠数值判据拦在发版之前。

## §10.4 验证纪律

本轮反复出现同一个模式：**尺子错了，却在量产品**。下面四条按踩坑频率排序。

### §10.4.1 度量本身要先被证伪

- **诊断脚本必须与被测对象共享配置**。预览脚本直接读源 PMX，把构建阶段已经丢弃的
  层（`hairspec`）也画出来（软渲染不做 alpha 混合 → 画成实心黑），
  于是"手臂/胸口/腿上有黑条纹、原本没有"这个结论追了很多轮贴图 ——
  问题在渲染器，不在资产。修法：`import` 构建脚本用的**同一份** `DROP_STEMS`，
  不要各写一份。
- **深度写入必须在 alpha test 之后**。软渲染里先写深度（用的是 alpha test **之前**
  的 `hit`）、后做 test，被剪裁掉的纹素仍占住深度，后面的几何填不进来，
  露出背景色 → 白衣服上一道道黑条纹。**GPU 是先测 alpha 再写深度的**。
- **统计"暗像素"要先排除背景**（背景本身就是暗的）。
- **`ib == -1`（背景/未覆盖）不能当索引 `-1` 用** —— 那会取到最后一个材质，
  得出"某层还在渲染"的错误结论。
- **分层口径换一次就要重建对照**（§11.19：按源位置分层 vs 按结果 z 分层，
  选出的是不同顶点集，数字不可比）。

### §10.4.2 预览"正常"不等于实机正常

预览与实机走的**不是同一条路**时，预览的"正常"没有证明力：

| 环节 | 预览走的 | 实机走的 | 因此查不出的问题 |
|---|---|---|---|
| UV | **源 PMX 的 UV**（不经 Blender / 导出器） | Blender → 导出器 `1−v` → xac | 贴图上下颠倒（§11.13） |
| 透明 | 简单 alpha test / 无混合 | `blendmode`（导出器硬编码，§9.8） | 叠加层盖黑、双面剔除（§11.15） |
| 深度 | 自研软渲染的写入顺序 | GPU 的 alpha test → 深度写入 | 重合层闪烁（§11.14） |
| mip | 通常只采第 0 级 | 完整 mip 链 | 远处摩尔纹（§11.17） |

**所以**：凡是"只有实机能看出来的症状"，都要在预览侧补一条**等价的数值判据**
（v 范围、层间距、mipCount、材质表），不要指望用预览复现它。

### §10.4.3 工具的"意图"不等于产物

构建脚本里写的 `ALPHA1`、注释里写的 "the exporter applies `1 - uv.y` itself"，
都不是证据：前者的成品是 **18/18 材质 `NONE`**，后者只对了一半。
**证据只能来自成品本身** —— 读打包后的 `material_library.xml`、
导入成品 `.xac` 量 UV。凡是"设置在某处、生效在别处"的环节
（材质、UV、骨架），判据一律取**成品**。
